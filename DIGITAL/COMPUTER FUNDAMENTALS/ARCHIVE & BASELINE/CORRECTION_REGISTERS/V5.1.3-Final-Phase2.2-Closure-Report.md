## 2. Item-by-Item Final Change Register

The table below documents every changed item from the Phase 2.2 Final Closure pass, the defect/review finding addressed, the corrected formulation, and the authoritative standard:

| # | Technical Area | Prior Formulation / Review Finding | Corrected Formulation (Phase 2.2 Locked) | Authoritative Standard & Section |
| :-: | :--- | :--- | :--- | :--- |
| **1** | **DNS 1232-Byte Buffer Sizing** | Stated that 1232 bytes guarantees zero fragmentation across every valid IPv4/IPv6 network. | **Removed zero-fragmentation guarantee.** Described 1232 bytes as a **conservative fragmentation-avoidance recommendation** (DNS Flag Day 2020: 1280B IPv6 min MTU - 40B IPv6 - 8B UDP). Kept 1400 bytes contextual as a practical resolver ceiling (RFC 9715) to avoid fragmentation on standard 1500B Ethernet links with tunneling overhead, not a universal protocol limit. | **RFC 9715 (Jan 2025)** / **RFC 6891** / **DNS Flag Day 2020** |
| **2** | **PCIe 6.0 x16 Bandwidth & FLIT Mode** | Claimed approximately 242 GB/s net bidirectional payload bandwidth as a universal figure. | **Retained 128 GB/s per direction (simplex) and 256 GB/s bidirectional raw maximum** for an x16 link under PAM4 (64 GT/s, 8 GB/s/lane). Completely removed the ungrounded 242 GB/s universal payload figure. Qualified that net application payload depends on TLP packet payload size and framing overhead under mandatory 256-byte FLIT mode (10B CRC + 8B FEC). | **PCI-SIG PCIe 6.0 Base Spec**, Section 3 & 4 |
| **3** | **Shor's Algorithm Runtime Formulation** | Cited an unsupported exact complexity expression $\mathcal{O}((\log N)^2 \log \log N)$ as a universal formula. | **Removed unsupported exact complexity expression.** Rigorously explained **polynomial-time quantum factoring threat** relative to input bit length $\log N$ (running exponentially faster than classical sub-exponential algorithms like GNFS), which compromises RSA, DH, and ECC, without asserting an unverified universal exact runtime formula. | **NIST FIPS 203/204/205** / **Peter W. Shor (1994)** |
| **4** | **CMOS Dynamic Power Equation** | Ambiguous switching activity factor $\alpha$ definition, risking conflation between $0 \to 1$ and total transitions. | **Standardized and harmonized equation and definition:** Formally defined $P_\text{dynamic} = \alpha \cdot C_L \cdot V_{DD}^2 \cdot f$ where $\alpha$ is strictly defined as the **probability of a power-consuming $0 \to 1$ logic transition per clock cycle** (energy $E = C_L V_{DD}^2$ drawn only on $0 \to 1$). Explicitly documented that if activity is defined by total transitions, a factor of $1/2$ applies ($P = \frac{1}{2} \alpha_\text{total} C_L V_{DD}^2 f$). | **Weste & Harris: CMOS VLSI Design** (4th Ed., Sec. 4.4) |
| **5** | **DDR5 Refresh Modes & Parameters** | Generalized refresh timing ($t_\text{RFC} > 400\text{ ns}$) without exact table verification or density breakdown. | **Verified against exact JEDEC tables:** JESD79-5 Section 4.14 Table 169 establishes base 1x mode ($t_\text{REFW} = 32\text{ ms}, t_\text{REFI} = 3.9\text{ }\mu\text{s}$ at $T_\text{CASE} \le 85^\circ\text{C}$) and 2x mode ($t_\text{REFW} = 16\text{ ms}, t_\text{REFI} = 1.95\text{ }\mu\text{s}$ at $85\text{--}95^\circ\text{C}$). Refused to generalize $t_\text{RFC}$, explicitly detailing density-specific timing from Table 170: all-bank $t_\text{RFC1}$ is 195 ns (8Gb), 295 ns (16Gb), and 410 ns (24Gb); same-bank $t_\text{RFCsb}$ is 115 ns (8Gb), 130 ns (16Gb), and 180 ns (24Gb). | **JEDEC JESD79-5 / JESD79-5C**, Section 4.14 Table 169 & Table 170 |
