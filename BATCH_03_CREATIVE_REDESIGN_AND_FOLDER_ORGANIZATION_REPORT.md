## 3. Final Technical Refinements Summary

### A. TCP Architecture (Storyboard 1)
1. **Advertised MSS vs. Effective Data Payload:**
   - **Advertised MSS (RFC 793, RFC 879):** The Maximum Segment Size is exchanged strictly during the connection handshake within the initial `SYN` packet ($1500 - 20\text{B IP} - 20\text{B TCP} = \mathbf{1,460\text{ Bytes}}$). It is static for the entire session and is never renegotiated.
   - **Effective Per-Segment Data Payload:** When an individual segment carries TCP options (e.g. 12-byte RFC 7323 Timestamps), the TCP header expands from 20 to 32 bytes. The effective payload space for user data on that specific segment is reduced from $1,460$ down to $\mathbf{1,448\text{ Bytes}}$ ($1500 - 20 - 32 = 1448\text{B}$).
   - **Enforced Rule:** We never state that the advertised MSS automatically changes to 1448 bytes.
2. **Approximate Segmentation Label:**
   - Slicing a 10GB video is explicitly labeled as **"~7 Million Segments (Approximate)"**, noting that the exact segment count depends on the per-segment payload size (~6.85M segments at 1,460B MSS vs ~6.91M segments at 1,448B payload with options).
3. **Mobile Readability:**
   - Static dense text blocks replaced with scannable visual chunks, larger font scales, and clean padding.

---

### B. Facebook BGP Outage (Storyboard 2)
1. **Unrelated Phrase Removed:** The phrase *"Physical Badge Scanners at Datacenter: OFFLINE"* has been removed from all graphics and narration.
2. **Accurate Failure Sequence:**
   - **Phase 1 (Backbone Maintenance):** A command issued during backbone capacity testing severed internal data center connectivity (Meta Postmortem).
   - **Phase 2 (DNS Route Withdrawal):** Meta's automated DNS health checks withdrew BGP route advertisements for authoritative DNS nameserver prefixes when those servers lost communication with backend data centers.
   - **Phase 3 (Layer 3 Unreachability):** Meta's authoritative nameservers (`a.ns.facebook.com`... `d.ns.facebook.com`) were powered on and running, but no incoming IP packet could reach them over the Internet. Zero queries reached them. Authoritative nameservers did not send responses.
   - **Phase 4 (Recursive Resolver SERVFAIL):** Public DNS resolvers (Cloudflare `1.1.1.1`, Google `8.8.8.8`) and ISP caching resolvers queried Meta's authoritative server IPs. Packets timed out in transit. Upon timeout expiration (RFC 1035 / RFC 2308), the **recursive resolver synthesized and returned `SERVFAIL` (RCODE 2)** to client devices.
3. **Strict Separation of SERVFAIL (RCODE 2) and NXDOMAIN (RCODE 3):**
   - `SERVFAIL` = Resolution infrastructure/timeout failure (domain exists, but lookup failed).
   - `NXDOMAIN` = Authoritative confirmation that the domain does not exist in the zone.
   - They are fundamentally distinct and never conflated.
4. **Client UI Error Independence:** Browser error messages (e.g., `ERR_NAME_NOT_RESOLVED`) are explicitly identified as client application UI strings, not DNS protocol RCODEs.
5. **Primary Supporting References & Direct URLs:**
   - **Meta Engineering Official Postmortem:** [https://engineering.fb.com/2021/10/05/networking-traffic/outage-details/](https://engineering.fb.com/2021/10/05/networking-traffic/outage-details/)
   - **Cloudflare Official Technical Analysis:** [https://blog.cloudflare.com/october-2021-facebook-outage/](https://blog.cloudflare.com/october-2021-facebook-outage/)
