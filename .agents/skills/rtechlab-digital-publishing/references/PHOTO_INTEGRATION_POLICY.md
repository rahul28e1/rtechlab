# RTechLab Real Photograph & Technical Asset Integration Policy

## 1. Core Rule: Authentic Real Photography for Physical Objects
Whenever a chapter explains physical hardware, components, devices, ports, or tools, the authoring pipeline must fetch authentic, high-resolution photographs instead of relying solely on vector approximations.

## 2. Permitted Commercial Open-Access Sources
1. **Wikimedia Commons**: Permitted licenses: CC0, Public Domain, CC-BY, CC-BY-SA, Free Art License (FAL).
2. **Pexels**: Pexels commercial license.
3. **Manufacturer Technical Product Captures**: Permitted only when explicit commercial reuse authorization is documented.

## 3. Strict Exclusions
- Never use All-Rights-Reserved copyrighted images without explicit written permission.
- Never use Non-Commercial (NC) only licenses.
- Never use AI-generated hallucinated fake software screenshots or fictional hardware pins.

## 4. Visual Hybrid Formula: Real Photo + Vector Schematic
- **Real Photograph**: Demonstrates physical reality, surface texture, pin grids, solder pads, heatsink mass, and connector dimensions.
- **Annotated Vector Schematic**: Clarifies abstract data flow, circuit traces, pinout voltages, and mechanical tolerances.
- **Combined Impact**: Bridges theoretical comprehension with practical physical recognition in enterprise datacenters and desktop support environments.
